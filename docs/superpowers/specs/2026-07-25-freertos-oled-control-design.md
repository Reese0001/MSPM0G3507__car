# FreeRTOS、SSD1306 与循迹控制升级设计

## 目标

在 MSPM0G3507 小车现有模块化工程上完成以下升级：

- 使用 TI MSPM0 SDK 2.10.00.04 自带的 FreeRTOS 与 TI Arm Clang CM0+ 端口。
- 接入 0.96 寸 SSD1306 128x64 I2C OLED。
- 消除尖弯、直角和短暂丢线后 D1 常亮、电机永久停止的问题。
- 使用八路数字传感器的 15 位置开环查表控制，不使用 PID/PD。
- 提高直线平均速度，同时保持弯道精度和电机安全约束。
- 将任务周期、控制参数、速度和超时集中到配置文件。

不引入第三方 RTOS、显示库或动态内存。

## 已确认硬件

| 模块 | 引脚/接口 | 说明 |
|---|---|---|
| 八路循迹 | PA15/PA16/PA17/PA18 | AD0/AD1/AD2/OUT |
| MPU6050 | PA12/PA13 | 软件 I2C，地址 0x68 |
| SSD1306 | PA10/PA11 | 软件 I2C，地址 0x3C |
| 电机驱动 | PB6/PB7 | UART1 |
| D1/D2 | PB2/PB3 | 故障/心跳 |

OLED 接线：

- GND -> GND
- VCC -> 3.3V
- SCL -> PA10
- SDA -> PA11

PA10/PA11 改为 GPIO 后不再提供 UART0 调试输出。OLED 负责显示运行诊断。

## 已定位故障

D2 持续闪烁说明主循环仍运行。D1 在尖弯、直角或丢线后常亮，符合以下软件路径：

1. `CornerManeuver` 的寻线或总动作超时进入永久故障。
2. `LineRecovery` 的旋转寻线或总恢复超时进入永久故障。
3. `AppScheduler` 将上述控制超时再次永久锁存。
4. 安全层拒绝后续运动请求，必须复位才能恢复。

赛道识别失败属于可恢复的控制事件，不应与电机通信失败、任务失活等真正安全故障共用永久锁存。

## FreeRTOS 架构

使用静态任务、静态队列和长度为 1 的最新值邮箱。FreeRTOS tick 为 1 kHz。

### SafetyTask

- 周期：1 ms。
- 优先级：最高。
- 检查传感器、控制和电机服务心跳。
- 对运动请求做新鲜度、速度上限和状态检查。
- 调用电机安全层并维持软启动。
- 只有电机 UART 失败、关键任务失活或关键数据长期过期才锁存 D1。

1 ms 电机安全计时仍由硬件定时器中断维护，不能依赖低优先级任务调度。

### SensorTask

- 周期：2 ms，使用 `vTaskDelayUntil`。
- 每周期完成一次八路循迹采样、15 位置解码并发布不可变快照。
- 每五个周期读取一次 MPU6050，即 100 Hz。
- 每次执行必须有时间预算，不调用毫秒级阻塞延时。
- 新快照通过直接任务通知唤醒 ControlTask。

### ControlTask

- 由 SensorTask 的新快照触发。
- 对稳定位置查表，计算基础速度、差速、转角和恢复状态。
- 发布最新运动请求与控制诊断。
- 电机 UART 命令最短间隔为 5 ms；2 ms 内的新结果覆盖旧结果，不排队。
- 不访问 OLED，不执行 I2C 传输。

### DisplayTask

- 周期：200 ms。
- 优先级：最低。
- 使用 PA10/PA11 独立软件 I2C。
- 只刷新发生变化的页面，限制单次传输量。
- OLED 缺失或传输失败只产生显示模块告警，不影响循迹和电机。

## 转弯与丢线恢复

赛道只有一条连续黑线，不实现双线选择或多段路径推理。

### 状态处理

- 直角寻线超时：从 `CornerManeuver` 转入 `LineRecovery`，不锁存 D1。
- 丢线后沿最后稳定位置对应的方向继续低速向前弧形盲走。
- 需要急转时采用同方向低速原地转向，不执行后退巡线。
- 连续 2 帧检测到稳定有效位置后进入低速对齐。
- 对齐稳定后恢复普通循迹。
- 搜索达到安全总时限后受控停车，但保持可重新启动，不设置永久控制故障。

### 永久故障范围

仅以下情况锁存：

- 电机 UART 帧发送失败。
- 电机安全心跳超过 200 ms 未更新。
- FreeRTOS 栈溢出或内存分配失败钩子被触发。
- 关键传感器任务长期不运行。

## 15 位置开环查表

从车头向前看，1 号传感器在最左侧，8 号在最右侧。正常单线只接受单灯和相邻双灯：

| 有效图样 | 稳定位置 |
|---|---:|
| 单灯 1～8 | -7、-5、-3、-1、+1、+3、+5、+7 |
| 相邻双灯 1+2～7+8 | -6、-4、-2、0、+2、+4、+6 |

共 15 个位置。每项直接查出 `base` 和 `diff`：

```text
left  = clamp(base - diff)
right = clamp(base + diff)
```

本项目电机由 UART 驱动板控制，表中的“PWM”实现为速度指令，不直接驱动 MCU PWM 引脚。

### 防抖与异常图样

- 每 2 ms 读取一次完整八路帧。
- 相邻位置变化立即接受，保证入弯响应。
- 跨越两个以上位置的跳变必须连续 2 帧一致才接受。
- 分离的多灯图样视为接线抖动或反光，保持上一稳定位置。
- 连续 3 灯以上只作为直角/宽线事件，不送入普通位置查表。
- 全灭表示丢线，保存最后稳定位置，不把全灭写成中心位置。

### 速度与 MPU 监督

- 普通循迹只使用查表结果，不运行 PID、PD 或积分器。
- 直线位置使用较高 `base` 和较小 `diff`。
- 越靠近边缘，逐级降低 `base` 并增大 `diff`。
- MPU6050 不参与普通差速计算；只在急转时限制过高角速度，并辅助确认出弯。
- MPU6050 无效时仍可纯查表循迹，速度限制约 280，并在 OLED 显示告警。

初始速度目标：

| 场景 | 指令目标 |
|---|---:|
| 稳定直线 | 400~430 |
| 普通循迹 | 340~370 |
| 普通弯 | 240~280 |
| 尖弯/找线 | 80~150 |
| MPU 降级上限 | 280 |

所有命令继续限制在比赛安全上限 450 以内。启动必须保留 0 到 30% 的渐进软启动，禁止直接满速。

## OLED 页面

主页面固定显示：

- `RUN / LIMITED / STOP / FAULT`
- 八路循迹位图
- 稳定位置、候选位置和防抖计数
- 左右轮最终命令
- MPU `OK / CAL / LOST`
- 转弯/恢复状态
- 故障码

故障码区分：

- `C-SEARCH`：转角寻线
- `L-LOST`：丢线恢复
- `M-UART`：电机 UART 故障
- `CTRL-HB`：控制任务心跳超时
- `SENS-HB`：传感器任务心跳超时
- `OLED-I2C`：显示通信失败

## 实施顺序

1. 建立 FreeRTOS 最小启动工程并保持电机默认停止。
2. 迁移安全任务和心跳，不改变控制算法。
3. 迁移传感器与控制任务，验证周期和数据新鲜度。
4. 修复控制超时的永久锁存语义。
5. 添加 SSD1306 驱动和诊断页面。
6. 引入 15 位置速度表、两帧防抖和 MPU 急转限幅监督。
7. 分阶段提高速度并进行悬空、低速、完整赛道测试。

每完成一个独立功能，运行主机测试和 TI Clang 构建，然后单独提交并立即 push。

## 首次上板检查

- OLED 使用 3.3V，PA10=SCL，PA11=SDA。
- 首次烧录只接 USB，断开 12.6V 电机电源。
- 确认 OLED 初始化和任务心跳后，将车轮悬空再接电机电源。
- 验证软启动、急停和 D1 故障显示后才落地测试。
