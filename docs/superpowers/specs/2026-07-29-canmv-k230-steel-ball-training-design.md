# CanMV-K230 钢球检测模型训练与部署设计

## 目标

将 `D:\Downloads\又撞一天钟钢球开源` 中的钢球 VOC 数据集重新训练为适用于亚博智能 CanMV-K230 的 YOLOv5n 检测模型，并生成可上传到开发板的 `steel_ball_320.kmodel` 与板端测试程序。

首阶段仅实现摄像头实时识别、检测框显示和检测结果打印，不连接 MSPM0，不发送电机控制命令。

## 已确认条件

- 开发板：亚博智能 CanMV-K230，机器标识 `k230_canmv_yahboom`。
- 固件：CanMV v1.4.3，构建日期 2026-01-20。
- 训练主机：Windows，NVIDIA GeForce RTX 5060 Laptop GPU，8 GB 显存。
- 数据集：1034 张图片、1032 个 VOC XML、单类别 `gz`、1175 个标注框。
- 两张无 XML 图片作为负样本保留；两组完全相同的图片必须进入同一数据划分，避免数据泄漏。
- 模型：YOLOv5n，输入尺寸 320×320，识别稳定优先。

## 数据准备

1. 读取 VOC XML，将边界框转换为 YOLO 的归一化 `class x_center y_center width height` 格式。
2. 将类别 `gz` 映射为类别编号 0。
3. 检查图片存在性、XML 可解析性、尺寸一致性、边界框范围和空框。
4. 无 XML 的两张图片生成空标签文件，作为负样本参与训练。
5. 对完全重复图片按 SHA-256 分组，确保同组图片不会跨越训练、验证和测试集合。
6. 按文件名中的拍摄时间段形成连续帧组，再以组为单位划分约 80% 训练、10% 验证、10% 测试。禁止逐图片随机划分，以免相邻视频帧造成验证指标虚高。
7. 固定随机种子并输出划分清单，保证训练可复现。

## 训练设计

- 使用官方 YOLOv5n 检测模型和 COCO 预训练权重。
- 输入尺寸固定为 320×320。
- 单类别训练，启用常规颜色、缩放、平移和水平翻转增强；避免会破坏比赛场景几何关系的激进增强。
- 首轮训练上限 150 epochs，启用 early stopping。
- 根据 8 GB 显存自动选择可运行 batch size，优先从 16 开始，显存不足时降至 8。
- 使用独立 Python 3.10/3.11 环境，不使用系统 Python 3.14。
- 保存最佳验证权重，而不是只取最后一个 epoch。

训练验收记录包括：precision、recall、mAP@0.5、mAP@0.5:0.95、混淆矩阵、训练曲线以及测试集可视化结果。除总体指标外，还需人工检查小钢球、多个钢球、无钢球画面的误检和漏检。

## ONNX 与 K230 转换

1. 将最佳权重导出为固定 batch=1、输入 320×320 的 ONNX。
2. 使用训练集代表性图片作为 PTQ 校准集，覆盖不同光照、距离、目标数量和空背景。
3. 使用与 CanMV v1.4.3 固件运行时兼容的 nncase/nncase-kpu 版本生成 K230 `kmodel`。首选验证 2.9.0 兼容链；若固件拒绝加载，以板端实际错误为依据调整版本，不升级或重刷固件。
4. 先在 PC 上分别运行 ONNX 与 kmodel，对输出形状和量化后检测结果进行比较。
5. 量化后若明显掉点，依次尝试扩大校准集、调整 PTQ 策略，再考虑模型结构或输入尺寸变化。

转换成功的最低条件：kmodel 可被模拟器加载，输出形状正确，代表性测试图片中的钢球检测结果与 ONNX 基本一致。

## 板端程序

板端 `main.py` 使用 CanMV v1.4.x 的 `PipeLine`、`YOLOv5` 和显示接口：

- 模型路径 `/data/steel_ball_320.kmodel`。
- 类别列表 `["gz"]`。
- 模型输入尺寸 `[320, 320]`。
- 首次置信度阈值 0.5，NMS 阈值 0.45；根据实拍结果调节。
- 实时画框、显示置信度，并在终端输出类别、置信度、中心坐标和框尺寸。
- 使用 `try/finally` 释放 KPU、摄像头、显示和媒体资源。
- 首次测试手动运行；稳定后才保存为 `/sdcard/main.py` 自动启动。

## 验证顺序

1. 数据检查通过，所有有效图片都能找到标签或被明确标记为负样本。
2. 在 PC 上训练并评估 PyTorch 模型。
3. 在 PC 上运行 ONNX，确认检测结果与 PyTorch 一致。
4. 转换并模拟运行 kmodel，确认量化误差可接受。
5. 将 `steel_ball_320.kmodel` 上传至 `/data`，先用单张图片验证模型能加载。
6. 再运行摄像头实时检测，记录帧率、误检、漏检和稳定性。
7. 板端识别通过后，另开阶段设计 K230 到 MSPM0 的 UART 坐标协议和失联保护。

## 错误处理与回退

- 依赖安装失败：保留锁定版本与日志，优先更换独立环境，不污染系统 Python。
- GPU/CUDA 不可用：先诊断 PyTorch CUDA 版本；必要时可回退 CPU，但不作为首选。
- ONNX 导出失败：固定兼容 opset，并去除动态输入。
- kmodel 无法加载：首先核对 nncase 与固件兼容性，而不是重新训练。
- kmodel 精度下降：扩大校准数据并比较不同 PTQ 选项。
- 板端内存不足：先减小摄像头推理帧尺寸或缓冲配置；模型输入仍保持 320×320。只有确认模型本身超限时才回退至 224×224。
