# MSPM0G3507 小车模块化传感器与安全控制设计

日期：2026-07-22
状态：已完成分节讨论，等待用户对本文档最终审核
目标平台：MSPM0G3507 + 两驱 L 型 520 编码器底盘 + 八路灰度 + YbImu 九轴 IMU + HC-SR04 + K230 豪华版（64GB TF 卡）

## 1. 目标与边界

本次升级把现有单一循迹程序重构为面向电赛的模块化小车平台。平台必须能够在赛题公布后，用有限的任务编排改动组合以下能力：

- 稳定循迹、弯道提前减速和丢线恢复；
- 编码器定距、IMU 定角和速度分段；
- K230 视觉事件识别；
- 固定朝前超声波紧急避障；
- 任务超时、传感器失效和通信中断时安全停车；
- 通过集中参数、遥测和离线测试快速调试。

本设计不实现 SLAM、MPC、在线地图或由 K230 直接控制电机。超声波不参与测绘或日常转向，只承担前向限速和急停。K230 是感知协处理器，MSPM0G3507 始终保留最终运动控制权。

## 2. 已确认硬件合同

### 2.1 主控与底盘

- 主控：TI MSPM0G3507，裸机、TI Arm Clang、CCS Theia；
- 底盘：228mm × 148mm × 102.15mm 两驱 L 型 520 编码器底盘；
- 驱动轮：M2、M4；M1、M3 不使用；
- 电机驱动通信：UART1，PB6 TX、PB7 RX，115200；
- 电机驱动板承担左右轮底层速度闭环，上位应用只请求目标轮速或车体速度；
- 调试串口：UART0，PA10 TX、PA11 RX，115200。

### 2.2 八路灰度

- PA15 = AD0、PA16 = AD1、PA17 = AD2、PA18 = OUT；
- 通过 3 位选通依次读取 X1～X8，不是 I2C 设备；
- 代码当前约定低电平代表黑线，高电平代表白底，实车必须再次确认；
- X1～X8 的物理左右顺序必须通过逐路遮挡测试确认。

### 2.3 YbImu 九轴 IMU

- 使用 I2C，地址 `0x23`，建议 100kHz；
- PA12 = SCL、PA13 = SDA；
- 连接 3.3V、GND；
- 目标更新率 100Hz；
- 新模块替代 MPU6050/eMPL 的活动运行路径。旧实现可在迁移期保留作回滚证据，但不得与 YbImu 同时参与控制；
- 安装完成后必须做静止零偏、坐标方向和磁校准。

磁力计靠近电机、线束和钢制结构时容易受干扰。因此正常转向主要使用陀螺仪短时相对角度；磁航向只有在健康检查通过时才可低权重校正，不作为急弯、找线或紧急动作的唯一依据。

### 2.4 HC-SR04 超声波

- 模块固定朝车头正前方，不带舵机；
- PA26 = Trig、PA27 = Echo；
- 触发周期初值 60ms，回波等待上限初值 30ms；
- 必须使用定时器捕获或边沿时间戳，禁止 `while` 等待 Echo；
- Echo 按 5V 信号处理，在进入 MSPM0 前必须通过分压或电平转换降到 3.3V 安全电平；
- 无有效回波必须结束本次测量并上报状态，不得阻塞调度器。

### 2.5 K230 豪华版

- 板卡：K230 豪华版，带 64GB TF 卡；
- K230 5V、GND 与主控扩展板共地；
- PA21 TX → K230 IO10/RX1；
- PA22 RX ← K230 IO9/TX1；
- UART 115200；
- K230 工程独立放在与 CCS 工程并列的 `K230_Vision/`，不放入 MCU 编译目录。

K230 只发送结构化感知事件，例如目标 ID、相对位置、角度、置信度、序号和采集时间。MSPM0 对长度、类型、数值范围、帧边界和时效进行验证后才使用。

### 2.6 电源红线

现有扩展板标注输入范围为 5～12V，用户电池满电为 12.6V。扩展板提供 5V 输出不等于其输入端允许超过 12V。

在以下任一安全条件满足前，系统不得从 `BOOT_SAFE` 进入 `RUNNING`：

1. 使用输入不超过 12V 的合规电源；或
2. 增加额定能力满足 MCU、传感器和 K230 峰值负载的降压/稳压方案；或
3. 取得扩展板制造商对 12.6V 连续输入的明确书面允许，并完成实测验收。

电源验收至少包括：输入电压、5V 空载电压、K230 启动压降、所有逻辑模块工作时电压、10 分钟温升和电机启停干扰。未经验证，禁止把 12.6V 满电电池直接作为扩展板长期工作输入。

## 3. 总体架构

系统采用安全监督式分层结构：

```text
application
    ↓
modules
    ↓
bsp
    ↓
TI DriverLib / SysConfig generated files
```

依赖只允许向下：

- `application/` 可以调用 `modules/`；
- `modules/` 可以调用 `bsp/`；
- `bsp/` 可以调用 DriverLib；
- `bsp/` 不知道业务状态；
- 传感器模块不得直接调用电机模块；
- K230、IMU、灰度和超声波只能发布快照或事件；
- 只有 `SafetySupervisor` 可以批准最终运动请求；
- 最终速度仍必须进入 `MotorSafety`。

## 4. 统一数据契约与调度

每个传感器模块发布不可变快照，至少包含：

```c
typedef struct {
    uint32_t timestamp_ms;
    uint16_t sequence;
    uint8_t valid;
    uint8_t health;
} ModuleStatus;
```

业务层只读完整快照，不直接读取驱动全局变量。生产者完成数据后再更新序号，消费者用序号和时间戳判断是否为同一帧、是否过期。

建议初始周期：

| 任务 | 目标周期/约束 |
|---|---|
| SafetySupervisor / MotorSafety | 1ms 时间基，不得被外设等待阻塞 |
| 灰度完整帧 | 目标不超过 2ms，MUX 稳定时间实测后配置 |
| 运动控制 | 5～10ms，使用同一时间戳的完整灰度帧 |
| YbImu | 10ms |
| 超声波触发 | 60ms；30ms 回波超时 |
| K230 UART | 中断接收 + 环形缓冲，主循环增量解析 |
| 遥测输出 | 低优先级、限带宽，禁止阻塞控制任务 |

当前 `Gray_ReadChannel()` 的每路 `delay_ms(1)` 会让完整扫描至少阻塞约 8ms。新设计必须把选通、稳定、采样和通道推进改为非阻塞扫描状态机；实际稳定时间以示波器测量为准，不直接假设 10μs 一定足够。

## 5. 安全监督状态机

### 5.1 状态

```text
BOOT_SAFE → READY → RUNNING ↔ LIMITED
    └──────────────→ STOP_LATCHED / FAULT
```

- `BOOT_SAFE`：电机固定零速，完成电源和模块自检；
- `READY`：等待 K1 明确启动；
- `RUNNING`：正常任务；
- `LIMITED`：近障、低置信度或降级条件下限制速度；
- `STOP_LATCHED`：障碍过近、人工急停或恢复失败，零速锁存；
- `FAULT`：watchdog、关键总线错误、关键传感器超时或内部合同违规。

解除 `STOP_LATCHED` 必须先满足安全恢复条件，再由 K1 人工确认。`FAULT` 只允许重新初始化或复位解除，不能由旧数据自动恢复。

### 5.2 初始安全门限

以下数值仅为配置起点，实车测试后调整：

- 超声波距离 `≤20cm`：进入 `STOP_LATCHED`；
- `20～35cm`：进入 `LIMITED`；
- 恢复要求：距离 `>40cm` 连续 5 个有效样本，并按 K1 确认；
- 视觉任务中 K230 连续 300ms 无有效帧：停车；
- 非视觉任务中 K230 掉线：标记降级，不影响灰度基础循迹；
- IMU 在定角或找线状态中过期：停止当前动作，禁止沿用旧 yaw；
- 电机命令 watchdog：保留现有 200ms 失控保护。

安全优先级从高到低为：

1. MotorSafety watchdog 和硬故障；
2. 超声波前向急停；
3. 当前任务关键传感器超时；
4. 路线、循迹或视觉运动请求。

## 6. B 级分层算法能力库

### 6.1 灰度线状态估计

八路二值结果不再只输出一个误差，还要输出：

- 对称加权线位置；
- 有效通道数量；
- 位型连续性；
- 最近 5～10 帧趋势；
- 线置信度；
- 候选事件：普通线、急弯、宽黑区、停止线、路口、全白丢线。

所有 256 种位型必须在离线测试中有确定结果。宽黑区不能单帧直接解释为停止线或路口，必须结合持续时间、里程计门控和当前任务上下文。

### 6.2 预测式循迹与速度规划

正常循迹首先采用有界 PD，不默认启用积分：

```text
e_pred = e + prediction_horizon × de/dt
turn = Kp(speed) × e + Kd(speed) × de/dt
```

- `e_pred` 用于提前识别入弯趋势；
- 根据预测误差、偏航角速度、线置信度和事件类型生成目标速度；
- 直道逐步加速，入弯提前减速，低置信度继续降速；
- 使用速度相关的增益档位，而不是所有速度共用一组 PID；
- 目标速度使用梯形或简化 S 曲线限制加速度和减速度；
- 普通循迹修正必须限幅，不能因 PD 数值过大偶然使一侧车轮反转；
- 状态切换时清除积分和旧误差，避免重新上黑线后猛冲。

### 6.3 急弯与丢线恢复

状态机：

```text
FOLLOW → HARD_CURVE → LOSS_CONFIRM → PIVOT_SEARCH
                                  → REACQUIRE → ALIGN → FOLLOW
                                  → RECOVERY_FAULT
```

- `HARD_CURVE`：连续趋势到达边缘时，允许内轮低速反转、外轮低速正转；
- `LOSS_CONFIRM`：连续多帧无黑线后才确认丢线；
- `PIVOT_SEARCH`：按照最后有效误差和趋势决定左右搜索方向，并记录 `yaw_start`；
- `REACQUIRE`：连续多帧重新识别黑线；
- `ALIGN`：限时渐进切回普通循迹；
- `RECOVERY_FAULT`：超过转角或时间仍未找线，锁定停车。

初始配置起点：

| 参数 | 初值 |
|---|---:|
| `LOSS_CONFIRM_COUNT` | 3 |
| `REACQUIRE_COUNT` | 3 |
| `PIVOT_FORWARD_SPEED` | 18% |
| `PIVOT_REVERSE_SPEED` | 12% |
| `MAX_RECOVERY_YAW` | 45° |
| `RECOVERY_TIMEOUT` | 800ms |
| `ALIGN_DURATION` | 300ms |

IMU 在此只提供相对转角边界，不判断黑线位置。整车不执行双轮同时反转的倒车找线。任何恢复状态都可被超声波、安全 watchdog 或传感器超时立即打断。

### 6.4 编码器与 IMU 分工

- 左右编码器：轮速、距离、两轮差速推算转角；
- 陀螺仪：短时相对 yaw 和 yaw rate；
- 磁力计：仅在健康条件良好时提供低频、低权重校正；
- 直线和定角控制使用简单可解释的互补校正，第一阶段不引入 EKF；
- 轮径、有效轴距、左右轮比例和停止距离必须通过实车标定；
- 若坡道题出现，可用 pitch 识别坡度并启用可关闭的速度前馈，但不纳入基础循迹默认路径。

### 6.5 运动基元

应用层提供可组合、非阻塞的运动基元：

```text
FollowLine(until_event, speed_profile)
DriveDistance(distance_cm, heading)
TurnRelative(angle_deg)
SearchLine(direction, max_yaw, timeout)
StopAtMarker(offset_cm)
WaitVision(event, timeout)
```

`MissionManager` 只编排基元和事件，不直接访问 GPIO、UART 或电机协议。现有 `Questions` 中重复的 Q1～Q4 控制流程将逐步迁移为数据化路线步骤，避免复制控制代码。

## 7. K230 通信设计

参考资料使用 `$` 起始、长度、示例 ID、逗号字段、`#` 结束并换行的文本帧。新实现兼容其基本格式，但必须增加严格校验：

- 起始和结束字符；
- 声明长度与实际长度；
- 支持的消息 ID；
- 字段数量；
- 数字范围和符号；
- 最大帧长；
- 超时丢弃；
- 环形缓冲溢出计数；
- 序号、置信度和数据时间戳。

UART ISR 只收字节入环形缓冲；解析器在主循环中增量运行。错误帧不得覆盖最后一份有效快照。业务层必须同时检查 `valid` 和数据年龄。

## 8. 参数、标定与遥测

### 8.1 参数档

至少提供三档：

- 安全档：第一次上车和未知赛道，速度不高于 30%；
- 稳健档：完成标定后的正式基础档；
- 冲刺档：只在完整回归通过后启用。

所有安全阈值、周期、控制增益、速度限制和标定值集中在配置头文件，不散落在状态机中。安全上限不得被普通任务档覆盖。

### 8.2 标定向导

开机或测试工具应支持：

- 灰度左右顺序、极性和各通道自检；
- IMU 静止零偏、安装轴向和磁校准状态；
- 左右轮正方向和速度一致性；
- 有效轮径、轴距、每厘米编码器计数；
- 直线停车距离和角度转向误差；
- 超声波固定距离点校验；
- K230 串口自检和视觉置信度阈值。

### 8.3 遥测

UART0 输出限频定长遥测，至少包含：

- 灰度位型、误差、预测误差和置信度；
- 左右轮目标/反馈、距离；
- yaw、yaw rate、IMU 健康度；
- 超声波距离和有效标志；
- K230 事件、置信度和数据年龄；
- 当前任务、控制状态、安全状态和最近停机原因；
- 各周期任务最大执行时间与超期计数。

MCU 保留最近故障的 RAM 环形日志。K230 可在 TF 卡保存视觉事件和必要图像，但其日志不能替代 MCU 的安全状态记录。

## 9. 独立工作树设计

实施时创建以下分支/工作树：

1. `codex/modular-foundation`：目录、公共接口、快照契约、调度器和配置框架；
2. `codex/ultrasonic`：非阻塞测距、滤波、超时和离线测试；
3. `codex/ybimu`：I2C 驱动、姿态快照、校准与健康状态；
4. `codex/k230-link`：UART 环形缓冲、协议解析和 K230 示例工程；
5. `codex/adaptive-line-control`：非阻塞灰度扫描、线状态估计、预测 PD、速度规划、恢复状态机和运动基元；
6. `codex/sensor-safety-integration`：统一 SysConfig、引脚、安全监督器和整车集成。

后三个传感器/控制工作树都以已审核的 modular-foundation 提交为共同基线。模块分支不各自永久修改 `empty.syscfg`；唯一的最终 SysConfig 与引脚集成发生在 `sensor-safety-integration`，避免并行分支冲突和生成文件漂移。

每个工作树都必须有独立提交、测试证据和回滚点。未经模块验收不得进入集成分支。

## 10. 测试与验收矩阵

### 10.1 离线逻辑

- 遍历全部 256 种灰度位型；
- 验证误差对称性、置信度、趋势、宽黑区和丢线事件；
- 验证状态机的正常、超时、取消和故障路径；
- 对 K230 协议做截断、粘包、分包、乱码、超长帧、字段越界和缓冲溢出测试；
- 对超声波做无回波、超时、异常脉宽和抖动测试；
- 验证任何模块不能绕过 SafetySupervisor/MotorSafety；
- 验证 soft-start、限速和 200ms watchdog。

### 10.2 模块上板

电机电源断开，逐一验证：

- 灰度完整扫描周期、极性和顺序；
- YbImu 地址、100Hz 更新、静止漂移和轴向；
- HC-SR04 固定距离、超时和 Echo 电平；
- K230 启动、UART 帧、掉线和重连；
- 主循环和 1ms 安全服务无阻塞；
- 最大执行时间和超期计数满足预算。

### 10.3 电机 Checklist

任何非零电机测试前必须确认：

- 驱动轮架空并可立即切断电机电源；
- M2/M4 与左右轮映射；
- 正负速度对应的物理方向；
- PB6/PB7 串口交叉、波特率和共地；
- 零速帧有效；
- soft-start 从 0 渐进到不高于 30%；
- 200ms watchdog 失联后可靠清零；
- 超声波急停可打断所有运动状态。

### 10.4 实车路线

依次测试：

1. 安全档直线和人工急停；
2. 中线、缓弯、连续弯；
3. 直角与明确的单轮反转 HARD_CURVE；
4. 短时丢线、恢复、超角度和超时停车；
5. 障碍物限速、急停、锁存和人工恢复；
6. 编码器定距、IMU 定角和停止线偏移补偿；
7. K230 事件触发与掉线停车；
8. 所有模块同时运行的长时间压力测试；
9. 稳健档回归；
10. 所有前置项目通过后才评估冲刺档。

每次调参只改变一类参数，并保存遥测。离线可编译、可烧录、架空轮运行和落地赛道稳定必须作为四个不同结论记录。

## 11. 最终接线顺序

实施结束后交付图文接线表，按以下顺序执行：

1. 所有电源断开，核对扩展板丝印和接插件方向；
2. 只接逻辑地，确认 MCU、扩展板、电机驱动、灰度、YbImu、HC-SR04、K230 共地；
3. 接 YbImu：3.3V、GND、PA12 SCL、PA13 SDA；
4. 接灰度：电源、GND、PA15/PA16/PA17、PA18，并确认模块允许的供电电压；
5. 接 HC-SR04：5V、GND、PA26 Trig，Echo 经确认过的电平转换后接 PA27；
6. 接 K230：5V、GND、PA21 TX→IO10/RX、PA22 RX←IO9/TX；
7. 接电机 UART：PB6 TX→驱动板 RX、PB7 RX←驱动板 TX；
8. 暂不接电机动力电源，先用万用表检查短路和各逻辑电压；
9. 通过电源验收后，逐个模块通电并测试；
10. 最后接电机动力电源，架空轮执行电机 Checklist；
11. 所有架空测试通过后才落地低速测试。

最终接线图必须明确每根线的两端、供电电压、是否交叉、是否需要分压，并根据用户提供的实物照片再次核对接插件方向。任何实物丝印与本文档不一致时，以停电测量和厂商资料为准，不靠颜色猜线序。

## 12. 明确不采用的方案

- 不让 K230 直接发送电机 PWM/轮速命令；
- 不把超声波用于连续路线控制；
- 不在 ISR 中做协议解析、浮点控制或阻塞打印；
- 不在主循环中使用外设 `while` 等待或毫秒级逐路阻塞扫描；
- 不用单帧全白、全黑或视觉结果直接切换高风险运动状态；
- 不在普通循迹 PD 中允许意外单轮反转；
- 不复制其他项目的 PID、轴距、轮径和速度数值；
- 第一阶段不引入 EKF、MPC、SLAM 或持续视觉闭环；
- 不因扩展板有 5V 输出而忽略 12.6V 输入超过其 12V 标称上限的问题。

## 14. 完成标准

设计实现完成必须同时满足：

- 目录、依赖和参数实现模块化；
- 三个新硬件模块独立可测、可禁用、可降级；
- 安全状态机能够覆盖近障、超时、掉线、丢线和 watchdog；
- B 级循迹算法支持趋势预测、速度规划和受限找线；
- 编码器/IMU 运动基元可被任务管理器组合；
- 所有外设非阻塞运行并有时间预算；
- 电源和 Echo 电平通过硬件验收；
- 工作树、测试记录、接线表和调参日志齐全；
- 未经安全层批准，不存在任何非零电机输出路径。
