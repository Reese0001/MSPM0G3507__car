# OLED 流动调试日志设计

## 目标

SSD1306 仅作为板载调试终端。程序从 RESET 开始记录关键行为，OLED
显示最近 8 条日志；小车卡住后，通过最后一条日志判断程序停在哪个阶段。

## 显示规则

- 屏幕共 8 行，每行一条 ASCII 日志。
- 新日志写入第 8 行，旧日志整体上移一行。
- 只保留最近 8 条，不使用固定仪表盘。
- 单行格式为 `时间 事件 参数`，时间为启动后的毫秒数。
- 每行最多 21 个字符，超过部分截断，禁止动态内存。

示例：

```text
0000 BOOT
0012 OLED OK
0020 UART SILENT
0040 WAIT K1
1250 K1 PRESS
1252 MOTOR CFG
1755 MOTOR ARM
1800 TX L030 R030
```

## 启动与电机行为

1. RESET 后初始化时间基准、OLED、按键、传感器和任务。
2. OLED 初始化成功后记录 `OLED OK`；失败时继续周期重试，不影响安全逻辑。
3. K1 确认按下前，电机 UART 不发送配置帧或速度帧，并记录
   `UART SILENT`、`WAIT K1`。
4. K1 消抖确认后记录 `K1 PRESS`，再进入电机配置阶段。
5. 电机配置开始和完成分别记录 `MOTOR CFG`、`CFG OK`。
6. 安全层成功进入运行状态后记录 `MOTOR ARM`。
7. 软启动继续执行现有 0→30% 限幅；每次实际速度变化记录
   `TX Lxxx Rxxx`。
8. UART 超时、看门狗、方向切换等待和循迹丢线必须记录明确事件，
   不允许只显示通用 `ERROR`。

## 日志模块

新增独立的 OLED 事件日志模块，使用固定长度环形缓冲区：

- 8 条记录；
- 每条最多 21 个字符；
- 无 `malloc`；
- 写入函数不可直接访问 OLED；
- DisplayTask 每 100 ms 获取快照并刷新屏幕；
- 控制任务和安全任务只提交短事件，OLED I2C 阻塞不能反向影响控制。

重复的周期事件不连续刷屏。速度日志仅在左右实际命令变化时写入，
相同故障只记录第一次。

## 首批事件

| 事件 | 含义 |
|---|---|
| `BOOT` | 主程序进入 |
| `OLED OK` | SSD1306 初始化成功 |
| `OLED FAIL` | OLED 初始化或刷新失败 |
| `UART SILENT` | 电机 UART 尚未允许发送 |
| `WAIT K1` | 等待 K1 启动 |
| `K1 PRESS` | K1 消抖后确认按下 |
| `MOTOR CFG` | 开始配置 L 型 520 |
| `CFG OK` | 电机配置完成 |
| `MOTOR ARM` | 安全层允许电机运行 |
| `TX Lxxx Rxxx` | 实际提交给电机驱动板的左右速度 |
| `DIR WAIT` | 方向切换零速等待 |
| `UART TIMEOUT` | 电机 UART 发送超时 |
| `WATCHDOG` | 电机命令看门狗触发 |
| `LINE LOST` | 循迹线丢失 |

## 安全约束

- 诊断首测时驱动轮必须架空。
- 先关闭 12.6V，RESET 并看到 `WAIT K1` 后，再给驱动板上电。
- 未确认驱动板的通信丢失停车行为前，不允许在电机运行时按 RESET。
- 不取消现有软启动、命令限幅、方向切换停顿和看门狗。
- OLED 失败不得使电机继续运行，也不得绕过安全层。

## 验证

- 单元测试验证环形缓冲区只保留最后 8 条且顺序正确。
- 单元测试验证重复事件不会连续刷屏。
- 契约测试验证 K1 前没有电机配置或速度发送调用。
- 主机测试验证 K1 后按“配置 → ARM → 软启动”顺序执行。
- TI clean build 后生成新的 UniFlash TI-TXT。
- 首次实车测试只架空运行，记录 OLED 的完整启动日志。
