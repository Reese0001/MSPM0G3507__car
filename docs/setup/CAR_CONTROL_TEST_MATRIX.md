通过，才可进入下一阶段。阶段 1～3 属于软件验证，**禁止接入 12.6 V 电机电源**。

## 阶段 1：离线自动测试

```powershell
python -m unittest discover -s tests -v
```

保存测试数量、结果、提交号和日期。该结果只证明源码/文档契约；Python 参考模型
不能执行 ARM 目标代码。

## 阶段 2：目标翻译单元

现有 `tests/test_car_sensor_events.py` 会调用 TI Arm Clang，为 Cortex-M0+ 编译
实际 `car_sensor_events.c` 翻译单元。通过意味着该模块可被目标编译器接受，
不代表 SysConfig 生成、其他 BSP、链接脚本或最终映像正确。

## 阶段 3：CCS 完整构建

已通过 CCS 20.5.0 生成的 Debug makefile 执行 Clean/Build：SysConfig 1.26.2、
MSPM0 SDK 2.10.00.04 和 TI Arm Clang 4.0.4 均从当前安装路径解析，全部 C 文件编译并
成功链接 `MSPM0G3507_LineFollowing_Car.out`。构建只验证固件生成，不代表已烧录或实车验证。
本次链接结果：FLASH 使用 27,208 B，SRAM 静态使用 1,944 B；构建产物位于工程 `Debug/` 目录。

## 阶段 4：断电接线检查

- PA15/PA16/PA17 为灰度选通，PA18 为 OUT；不要按 I2C 接线。
- PA12/PA13 为 MPU6050 软件 I2C，传感器使用 3.3 V。
- PB6/PB7 为电机 UART，确认 TX/RX 方向和共地。
- M2 左轮、M4 右轮；M1/M3 不得收到非零命令。
- 满充 12.6 V 高于板卡图片的 5-12 V 标注。没有准确规格确认就停止。

## 阶段 5：架空轮与低电压

只使用经过确认、带限流和急停的低电压方案。先验证零速帧，再单轮低速，再双轮
低速；检查 0→30% 软启动和 200 ms 看门狗。首次验证禁止满速、禁止落地、禁止
无人值守。

电机反馈的年龄 **>= 200 ms** 必须触发故障停车。还要验证左右轮数据属于同一
帧/同一采样周期；在这些条件未确认前，不启用距离和角度动作。

## 阶段 6～8：传感器、赛道与路线

灰度 `CarSensorFrame` 没有时间戳或序列号，因此控制循环必须消费本周期
`CarSensor_ReadFrame` 刚生成的帧。不得把缓存帧重复交给 `CarRoute`。

先在静止状态记录八路电平，再验证基础 `LineWalking()`。`CarRoute` 已实现但
尚未接入 empty.c；只有基础循迹、停车路径和反馈新鲜度均通过，才允许单独提交
集成改动并重新从阶段 1 开始验证。

## 明确未覆盖

- 本矩阵不证明 12.6 V 可安全接入 5-12 V 标注的板卡；
- 不证明电机、编码器或 MPU6050 的实际方向和比例；
- 不证明距离/角度已经标定；
- 不包含摄像头测试，因为当前未购买摄像头；
- 不授权烧录后直接落地运行。
