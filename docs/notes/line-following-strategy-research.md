# 八路灰度循迹小车控制策略调研与本项目落地建议

日期：2026-07-18  
适用分支：`verify/line-following-car`  
目标平台：MSPM0G3507 + 八路灰度模块 + 两轮差速电机

## 1. 调研目的与边界

本文对用户提供的 10 篇循迹小车资料进行交叉整理，并结合本项目当前代码和离线审计结果，筛选可以采用的控制策略。

本项目已确认的灰度接口是 GPIO 选通读取，而不是 I2C：

- PA15 = AD0
- PA16 = AD1
- PA17 = AD2
- PA18 = OUT

因此，资料中的 I2C 地址、摄像头识别、步进电机位置模式、具体 PWM 数值和其他主控引脚不能直接复制。本文只吸收与硬件无关或能够明确适配的算法思想。

## 2. 资料中值得参考的共同策略

### 2.1 用对称加权位置代替超长模式判断

多篇方案把每一路灰度传感器映射为左右对称的位置权重，再对当前检测到黑线的通道取平均。八路传感器可先采用：

```text
X1   X2   X3   X4   X5   X6   X7   X8
-7   -5   -3   -1   +1   +3   +5   +7
```

若检测到黑线的通道集合为 `B`，位置误差为：

```text
error = sum(weight[i], i in B) / count(B)
```

这种方法能自然处理相邻两路或多路同时压线，并保持左右修正对称。相比逐一枚举大量 `if/else` 位型，它更容易测试，也不会因为漏掉某个位型而沿用错误的旧误差。第一篇资料还给出了从中心向边缘逐级增大的对称补偿，并利用相邻通道平均值处理连续触发；这与加权平均方法方向一致。[资料 1](https://blog.csdn.net/2201_75813159/article/details/149424165)

建议：本项目采用加权平均作为正常循迹的唯一位置误差来源；特殊路口、直角和丢线由状态机处理，不再混入普通误差表。

### 2.2 方向环输出只作为左右轮差速修正

资料中的常见结构是：

```text
左轮目标速度 = 基础速度 + correction
右轮目标速度 = 基础速度 - correction
```

循迹误差形成外层方向修正；如果电机或驱动板能提供可靠速度反馈，再由左右轮速度环保证目标速度。[资料 2](https://jishuzhan.net/article/2058419298512191490)

本项目当前电机通过 UART 驱动板控制，尚未确认闭环速度反馈质量，因此第一阶段只实现方向 PD，不虚构编码器闭环。正常循迹时必须限制 `correction`，建议：

```text
abs(correction) <= 0.8 * base_speed
```

这样正常修正不会让任一车轮突然反转。需要原地转向时，应由明确的弯道/找线状态执行，而不是由过大的 PID 输出偶然触发。

### 2.3 先用 PD，确认采样周期后再考虑积分项

本项目当前代码的 D 项使用了 `error_last`，但没有在每次计算后更新它，这是确定的逻辑缺陷。正确的离散形式应明确采样周期：

```text
derivative = (error - last_error) / dt
integral += error * dt
correction = Kp * error + Ki * integral + Kd * derivative
last_error = error
```

循迹初调建议令 `Ki = 0`，先调 P，再增加少量 D 抑制摆动。只有确认存在持续的机械偏差、左右轮差异且 P/PD 无法消除时，才启用积分，并添加积分限幅和状态切换清零，避免丢线或停车期间积分累积。

资料中的 PID 数值与电机、轮径、轴距、速度单位和采样周期绑定，不能直接用于本项目。部分资料中的 `while + delay_ms()` 控制写法也不适合当前协作式调度器。[资料 9](https://blog.csdn.net/2403_88996133/article/details/143780831) [资料 10](https://blog.csdn.net/m0_63210745/article/details/140764261)

### 2.4 根据偏差和检测置信度动态降速

直线时提高基础速度，偏差增大、检测通道异常增多或进入弯道时降低基础速度，是多篇资料的共同思路。第一篇资料明确使用变速循迹，并按传感器状态动态调整速度。[资料 1](https://blog.csdn.net/2201_75813159/article/details/149424165)

本项目建议采用保守的分级策略：

| 条件 | 基础速度建议 | 说明 |
|---|---:|---|
| `abs(error) <= 1` 且连续稳定 | 标定巡航速度 | 直线或接近中心 |
| `1 < abs(error) <= 3` | 巡航速度的 70%～80% | 普通弯道 |
| `abs(error) > 3` | 巡航速度的 40%～60% | 急弯或接近边缘 |
| 进入丢线恢复 | 不高于 30% | 只用于短时找线 |
| 丢线超时或状态不可信 | 0 | 安全停车 |

这里的百分比是相对策略，不是最终电机参数；仍需受现有 0→30% soft-start、安全看门狗和驱动板允许范围约束。

### 2.5 丢线要使用“历史方向 + 连续帧确认 + 超时停车”

单帧全白可能来自缝隙、反光或采样噪声，不应立即高速反向；但无限保留上一次误差也会导致失控。可以使用如下分阶段策略：

1. 检测到黑线时保存最后有效误差及其方向，丢线计数清零。
2. 连续丢线 1～2 个控制周期：以不高于 30% 的低速，按最后有效方向温和找线。
3. 第 3 个周期仍丢线：请求两轮零速并进入 `LINE_LOST`。
4. 只有连续重新检测到有效线位后才退出 `LINE_LOST`，防止单帧噪声误恢复。
5. 找线阶段同样受 200 ms 电机安全看门狗约束。

第一篇资料利用上一帧状态在黑线消失时保留方向信息，并通过持续时间阈值过滤状态变化；可借鉴其“历史值 + 去抖”思想，但本项目应采用短周期计数和明确停车上限，而不是照搬 100 ms 或其他固定数值。[资料 1](https://blog.csdn.net/2201_75813159/article/details/149424165)

### 2.6 用非阻塞状态机处理直角、出入圈和恢复

资料普遍把直线、弯道、角度控制和停止拆成状态。第一篇资料采用周期任务、命令超时与状态机，强调避免阻塞式 `delay`；第二篇资料强调灰度循迹与陀螺仪“交替盲走”；Turin 的复盘资料也展示了复杂赛题流程需要分段组织。[资料 1](https://blog.csdn.net/2201_75813159/article/details/149424165) [资料 2](https://jishuzhan.net/article/2058419298512191490) [资料 7](https://szturin.github.io/posts/37775/index.html)

建议把当前循迹控制拆为：

```text
TRACKING -> CORNER_LEFT / CORNER_RIGHT -> TRACKING
TRACKING -> SEARCHING -> TRACKING
SEARCHING -> LINE_LOST -> STOPPED
任意运行状态 -> watchdog fault -> STOPPED
```

状态持续时间使用毫秒计时或调度周期计数，不使用 `delay_ms(100)`。这样主循环能持续读取传感器、刷新电机安全服务和响应急停。

### 2.7 灰度和 IMU 分工，不在第一阶段强行融合

部分 2024 H 题方案在有线段用灰度闭环，在无线段或出入圈阶段用陀螺仪保持航向，并结合编码器或里程信息控制距离。[资料 2](https://jishuzhan.net/article/2058419298512191490) [资料 10](https://blog.csdn.net/m0_63210745/article/details/140764261)

这对比赛路径状态机有参考价值，但不应立刻混入基础循迹。建议分两阶段：

- 第一阶段：只验证八路灰度 + 两轮差速能够稳定循迹、丢线停车。
- 第二阶段：确认 MPU6050 零偏、漂移和更新周期后，只在明确的无线段或角度转向状态中使用航向控制。

## 3. 与当前代码审计问题的对应关系

| 当前问题 | 影响 | 建议修复 |
|---|---|---|
| D 项未执行 `error_last = error` | D 项不是相邻周期差分 | 修正离散 PD/PID 状态更新 |
| 全白时可能保留旧误差 | 丢线后继续按旧方向行驶 | 增加连续丢线计数、低速恢复和超时零速 |
| 直角分支包含 `delay_ms(100)` | 阻塞传感器更新和安全服务 | 改为非阻塞状态机 |
| `KP=400` 导致小偏差即车轮反转 | 易原地旋转、蛇形振荡 | 降低增益并限制修正量 |
| 大量位型 `if/else` | 难覆盖、难验证、容易遗留旧状态 | 改为对称加权误差 + 独立特殊状态 |

## 4. 推荐的落地顺序

1. 保留当前 PA15/PA16/PA17/PA18 采样方式，先验证 X1～X8 的物理左右顺序和黑白电平极性。
2. 增加纯函数式的八路加权误差计算，并用 256 种输入离线遍历测试。
3. 修复 `last_error` 更新，先启用 PD、关闭积分。
4. 加入方向修正限幅，保证普通循迹不反转车轮。
5. 加入 `TRACKING/SEARCHING/LINE_LOST/STOPPED` 非阻塞状态机，移除循迹路径中的 100 ms 阻塞延时。
6. 在离线测试、SysConfig 生成、TI Arm Clang 编译和链接全部通过后，再进行架空轮测试。
7. 架空轮确认 M2/M4 正方向和急停后，才以 0→30% soft-start 进行低速地面调参。
8. 基础循迹稳定后，再评估是否需要 MPU6050 航向段和速度反馈内环。

## 5. 不建议直接采用的内容

- 不复制其他工程的 PID、PWM、轮距、速度和时间阈值。
- 不把当前 GPIO 多路选通模块改写成资料中的 I2C 地址读取。
- 不采用摄像头/OpenCV阈值、舵机转向或步进电机位置模式代码。
- 不在主循环或循迹函数中使用长时间阻塞 `while`/`delay_ms()`。
- 不把单次全白直接解释为赛道事件，也不允许无限期保持旧误差。
- 不在正常循迹 PID 中允许左右轮意外反转。

## 7. 结论

这些资料支持当前离线审计的判断：本项目具备实现循迹的硬件接口和可编译调用链，但现有控制逻辑不适合直接上车。最小可行修复路线是：

> 对称加权误差 → 非阻塞 PD → 修正量限幅 → 连续丢线恢复/停车 → 状态机处理特殊弯道 → 低速实车调参。

这条路线与当前 GPIO 灰度采样、电机 UART 安全层和裸机调度器兼容，且能逐步验证，不需要先更换硬件架构。
