# MSPM0G3507 循迹小车项目宪章

## 核心原则

### I. 硬件证据优先

只依据已确认的实物、手册和 `empty.syscfg` 编写引脚及协议；不为尚未购买的摄像头或测距模块猜测接口。编码器脉冲、轮径和驱动板输入范围未实测前，必须标记为未验证。

### II. 电机安全不可绕过

所有电机请求必须经过 `Motor_Safety_RequestSpeed()`；启动使用 0→30% soft-start，保留 200 ms watchdog、故障锁存、快速断电和架空轮测试。任何新运动接口都不得直接调用 `Contrl_Speed()`。

### III. 先契约测试再实现

新增功能先写可失败的 Python `unittest` 契约测试，再实现 C 代码；每个任务必须运行覆盖测试并记录结果。CCS 编译是独立验收门，不能用离线测试替代。

### IV. 非阻塞与单一所有权

调度器任务和路线状态机必须非阻塞；传感器一次采样后由上层共享，禁止多个业务路径重复读取或在周期任务中使用长延时。`empty.syscfg` 是配置唯一来源，生成文件不得手改。

### V. 可追溯交付

每个任务保持独立提交，提交说明包含行为变化和验证命令；中文维护文档使用 UTF-8 无 BOM，现有 C 文件保持原编码。未跟踪的临时目录、构建产物和用户资料不得混入提交。

## 硬件与电源约束

- 当前平台为 MSPM0G3507、MSPM0 扩展板、四路编码器驱动板、两驱 L 型 520 编码器底盘和 MPU6050。
- 底盘初始尺寸为 228 mm×148 mm×102.15 mm，车轮标称 65 mm；有效轮径必须通过实测标定。
- 图片标注板卡输入为 5–12 V，电池满电为 12.6 V；确认绝对最大输入电压前禁止接入满电电池。
- 摄像头未购买，第一阶段只实现灰度、编码器、MPU6050 和路线控制。

## 开发流程与质量门

硬件规划 → 规格/契约更新 → 失败测试 → 最小实现 → 离线测试 → CCS 编译 → 架空轮验证 → 经确认后实车验证。遇到规格冲突必须先记录并取得确认；不得以“看起来兼容”替代电源、引脚或编码器验收。

## 治理

本宪章约束 `my-project` 生成的规格、计划和任务；与项目 `AGENTS.md` 或已确认硬件事实冲突时，以安全要求和最新硬件证据为准，并在规格中记录修订原因。模板和脚本只作为工具，不得把模板占位符当作项目规则。
